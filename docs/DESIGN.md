# ncmp 设计系统（v1.2 · 音乐合伙人评分）

本文件是**唯一的设计主张来源**。`app/ui/theme.py`（桌面）与
`android/.../ui/theme/Theme.kt`（手机）里的 token 必须与本文一致；
改设计先改本文，再改 token。

本次改版参考了开源项目 [Grails125/ncmm](https://github.com/Grails125/ncmm)
（网易云音乐多账号自动化管理工具，原生集成音乐合伙人评分、推荐歌曲笔记与乐评）：

- **抄什么**：把「评分」当成「留下一条批注」来做，而不是当成一次接口调用；
  以及把收益/统计做成一本可回看的账。
- **不抄什么**：多账号并行执行、Docker/WebUI 部署形态。
  本项目是本地桌面 + 手机端的单人工具，账号维度只做「切换」不做「并行」。

---

## 0. 一句话主张

> **这是一本每天自动填一页的值班簿，不是一台仪器。**

旧版把评分页做成「电平表 + 步骤树 + 日志」的控制台，用户看到的是机器在动，
看不到**今天评了哪几首歌、我给它们打了几分、我留下了什么话**。
新版把这三件事做成屏幕上的实体，机器状态退到后面。

## 1. 设计决策（以及对默认答案的否决）

| 决策 | 结论 |
|---|---|
| 品牌色 | **保留网易云红 `#C20C0C`**，不另立品牌色 |
| 深色模式 | 本轮做成一等主题（两端），不是把浅色反相 |
| 双端关系 | 共用 token 与组件语汇，**不共用页面骨架**：桌面双栏、手机单列 |
| 主视角 | **曲目表**（今日评了哪几首）是主，时间线/日志降级为折叠的「运行详情」 |
| 多账号 | 真做「登录 + 顶部切换 + 每账号独立配置与历史」，不做并行与跨账号汇总 |
| 批注来源 | 默认本地模板库，可选接自建 LLM（用用户自己的 key），失败回落模板 |

### 为什么否决"重建配色"

第一条我写下的方案是"下调红的明度、重建整套色阶"。否决理由：
本案的问题不在颜色——现有浅色板已经过对比度审计（`theme.py:24-55`），
红只用于"可交互"、琥珀只用于"进行中"，语义是干净的。
**问题在屏幕上没有任何一个"物"。** 换配色属于"什么都没解决但看起来改了"的动作，
所以把这次的胆量全部花在结构（曲目表/批注/档位标）与排版上，颜色只补深色一套。

|---|---|---|

| `PANEL` | `#FFFFFF` | 曲目表、面板、输入 |
| `INK` | `#1A1A1A` | 主文字 |
| `MUTED` | `#6B6B6B` | 次要文字（4.89:1） |
| `RULE` | `#E5E5E5` | 细线 |

| token | 值 | 说明 |

| `PANEL_DARK` | `#191C1F` | 面板浮起靠明度差，不用阴影 |
| `INK_DARK` | `#E8E9EA` | 正文（不是纯白，纯白在深底上发刺） |
| `MUTED_DARK` | `#9AA0A4` | 次要文字（4.52:1） |
| `RULE_DARK` | `#2A2E31` | 细线 |
| `BRAND_DARK` | `#E85256` | 提亮的红（4.63:1），深色下当文字/按钮都成立 |
| `RUNNING_DARK` | `#E0A85C` | 进行中 |
| `SUCCESS_DARK` | `#4FA97C` | 已提交 |
| `FAILED_DARK` | `#E06A5E` | 失败 |
| `TRACK_DARK` | `#2C3033` | 未点亮/占位 |

**深色不是反相**：浅色里"面板比底色白"的层级关系，在深色里靠"面板比底色亮一档"
维持同一个方向（面板永远比底亮），所以两套主题共享同一组层级语义。

## 3. 排版

字体不变（随包分发，OFL）：

- 展示 / 曲目号 / 档位标：`NCMP Serif SC`（宋体）
- 正文 / 界面：`NCMP Sans SC`（黑体）
- 日志（唯一等宽处）：`Consolas`

字号阶梯：`34 / 22 / 15 / 13 / 12`（新增 22 给日期与曲目名，替换旧的 20 标题档）。

### 三条排版规则

1. **曲目名用宋体、歌手用黑体灰字。** 宋体在 15px 下的竖画粗细差异，
   是"唱片内页"气质的来源；界面字用黑体保证小字清晰。
2. **批注（乐评文案）用宋体 13px、行高 1.7、左侧留 1px 竖线。** 它是"引文"，
   不是"数据"，所以不用等宽、不用灰底块。
3. **数字只在两处用等宽**：耗时/百分比等运行数据，以及日志。
   分数不用等宽——它属于展示层，用宋体的表格式数字（`4⁄5`），
   视觉上像内页上的手工标记，而不是仪表读数。

## 4. 组件

### 4.1 曲目行 `TrackRow`（本次的核心组件）

```
01 │ 歌名（宋体 15）                          4⁄5   ●已提交
   │ 歌手 · 时长（黑体 12，MUTED）            批注：「……」
```

- 序号：宋体 12，MUTED，右对齐两位（`01`…`12`）。**序号是合法的**——
  今日曲目本来就是一个有序队列。
- 档位标 `4⁄5`：宋体 15 + 斜线分隔，颜色随档位（4-5 用 INK，3 用 MUTED，1-2 用 FAILED）。
  不用星星，不用彩色胶囊。
- 状态：`已提交 / 待评 / 跳过 / 失败`，前面一个小圆点（6px），颜色用状态色。
- 批注：默认显示 2 行，超出省略，点行展开完整批注 + 「改一句」「重写」。
- 行分隔用 1px `RULE`；**不做卡片、不做阴影、不做圆角内缩**。

### 4.2 档位标 `TierMark`

`score⁄scale`，`scale` 取当日最高档（4 或 5）。这是全应用唯一的"分数表达"，
曲目行、账本、首页摘要共用。

### 4.3 运行详情 `RunDetail`（折叠）

旧的步骤树 + 日志原样保留，但收进 `<details>` 式的折叠区，默认收起，
**只在失败时自动展开**。这是"过程可见"的兜底，不再是主视角。

### 4.4 账本 `Ledger`

- 顶部三个数：`连续 N 天` / `累计 N 首` / `累计 N 条批注`
- 等级/权益位：`离下一档还差 N 首`（拿不到就整块隐藏，不显示占位符）
- 53 周格子图（沿用 `StreakGrid`）
- 每日一行，可展开看当日曲目与批注

│ 账号 ▾     │     歌手 · 03:42                            │ ─────────── │
│  阿树      │     批注：「……」（宋体 13/1.7，左侧竖线）  │ 运行详情  ▸  │

  执行按钮移到曲目表上方的工具条右侧（`立即执行 / 云端执行 / 取消`）。

## 6. 文案

用词表（全应用统一，不得混用同义词）：

| 用 | 不用 |
|---|---|
| 今日值班 / 今日评分 | 任务执行、跑任务 |
| 曲目 | 作品、歌曲列表、work |
| 批注 | 评论、comment、笔记 |
| 档位（4⁄5） | 星级、分数档 |
| 已提交 / 待评 / 跳过 / 失败 | 成功/失败（对单曲不够具体） |
| 账本 | 统计、数据看板 |
| 连续 N 天 | 连续登录、streak |

关键句：

- 空状态：「今天还没有排到曲子。点上面的「立即执行」评一次。」
- 首次进入批注功能（dry-run）：「这是第一次生成批注。先只生成、不提交——
  你看过觉得可以，再打开自动提交。」
- 全自动已开：「批注会随评分一起提交，可以在账本里回看每一条。」
- 失败：「这次没跑完：风控拦截。等 20 分钟再试，或改成云端执行。」
- 批注禁用时：「只评分，不写批注。」

**批注本身的三段式**（本地模板与 LLM 提示词共用这个骨架）：
一个具体的听歌场景 → 一句克制的判断 → 一句收尾（处置方式）。

## 8. v1.2 新增的六个小设计（编号 D1–D6）

评审时逐条定过，记在这里，避免以后被当成"随手加的"。

| 编号 | 是什么 | 为什么加 |
|---|---|---|
| **D1** | **策略预演**：用今天真实的待评歌单，本地算出四种评分策略各会给出什么，不提交、不改配置 | 把配置项变成"看得见后果的选择"。要求程序真的知道判定规则，所以别人抄不走 |
| **D2** | **口味曲线**：账本里一张 5/4/3/2/1 档的分布与占比 | 账本里唯一有情绪价值的东西——它照的是**你自己**，不是完成率 |
| **D3** | **三套语气**：克制 / 热络 / 简短，设置页可切 | 同一个默认语气服务所有人，结果谁都不像 |
| **D4** | **今日内页导出**：今天的曲目 + 批注存成 Markdown | 产品的身份感来自"它能产出东西"，而不只是完成率和日志 |
| **D5′** | **单曲留白**：这一首不写批注（本次留白） | 自动类工具最该有的那点尊重：默认自动，但允许你挑出一首 |
| **D6** | **等待倒计时**：随机等待的 15–20 秒显示成"再等 N 秒，避免触发风控" | 用户理解了为什么要等，就不会以为程序卡死 |

### 三条被否决/改写的提案（含理由）

- **D5 原案"锁住这一首"**：撤回。批注跟着评分**一次提交**，提交后改不了；而"记住这位作者我自己写"也不成立——服务端推的任务池里作者并不稳定复现。只保留"本次留白"这一层。
- **D3 第三套语气原叫"技术流"**：改名"简短"。写下第一句就发现它必须描述编曲和人声位置，**程序根本没听过这首歌**，那就是编造。语气可以是"说话的松紧"，不能是"知道得更多"。
- **D7 系列（年度内页 / 平行多账号 / 批注点赞回采）**：本轮不做。前两个是量级问题，第三个要额外接口与轮询、风控风险不明。

### 界面上的两个开关，语义要分清

- `note_enabled`：全局——**评分时要不要写批注**。
- 单曲留白（`note_muted_songs`）：局部——**这一首不写**。两者都不会影响评分本身。

## 9. 无障碍与工程底线

- 正文与背景对比度 ≥ 4.5:1（两套主题都验证）；非文字控件 ≥ 3:1
- 键盘焦点：2px 品牌色描边，控件外框尺寸不变（沿用现有做法）
- 尊重"减少动态效果"（桌面读 `MinAnimate`，手机读系统 animator 设置）
- 状态不只靠颜色：曲目行有 `已提交/待评/跳过/失败` 文字，色只是辅助
- 深色主题下 `METER_TRACK` 与 `RULE` 不得打平（层级要靠明度差撑着）
