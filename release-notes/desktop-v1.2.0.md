# 桌面端 v1.2.0 —— 从"一台仪器"变成"一本值班簿"

这次的重点是音乐合伙人评分这一环：评分不再是"机器在动"，而是**今天评了哪几首、
每首几分、留下了什么话**。方向参考了 [Grails125/ncmm](https://github.com/Grails125/ncmm)。

## 新增

- **批注（乐评文案）**：评分时同时提交一句批注，不再把 `comment` 留空。
  本地模板库生成，不联网、不调用 AI、不内置 key；同一首歌每次生成同一句。
- **三套语气**：克制（默认）/ 热络 / 简短，设置页可切。
  两条底线：不编造听觉细节（程序没听过这首歌）、不喊口号。
- **可选接自己的 LLM**：填 OpenAI 兼容 endpoint + 模型 + key 后 `note_source=llm` 生效，
  失败自动回落本地模板。
- **账本页**：每天评了哪几首、每首几分、留下什么话；累计曲目 / 累计批注 / 连续天数。
- **口味曲线**：你自己的 5/4/3/2/1 档分布与占比。
- **今日内页导出**：今天的曲目 + 批注存成 Markdown。
- **策略预演**：不提交、不改配置，用今天真实歌单算出四种策略各会给出什么。
- **单曲留白**：这一首不写批注。
- **等待倒计时**：随机等待显示成「再等 N 秒，避免触发风控」。
- **深色主题**：跟随系统深浅色。

## 改版

- 今日页主视角换成**曲目表**：序号 / 歌名（宋体）/ 档位 `4⁄5` / 状态 / 批注（宋体引文）。
- 步骤树与日志降级为默认收起的**「运行详情」**，只在失败时自动展开。
- 电平表保留，收成页头下方一条细带。
- 左导航「任务」→「今日」，新增「账本」。

## 工程

- 评分判定抽成纯函数 `core/scoring.py`（才能被预演和测试复用），行为不变。
- 新增 `core/notes/`（模板 / 生成器 / LLM）与 `app/track_log.py`，配套 24 个单测。
- 设计规范落到 [docs/DESIGN.md](../docs/DESIGN.md)。
